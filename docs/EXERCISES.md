# Exercises

Two kinds of practice, both done by hand, without AI (spec section 21):

1. **Break it, watch it fail, fix it.** Thirteen one-line sabotages. Each one is caught by a
   specific test, and seeing which one, and why, is the lesson.
2. **Write the † commands.** The 25 commands left out of the build on purpose. Each is small,
   and each exercises one idea the codebase already has.

Run the suite named in each exercise before you start, so you know it's green. Undo the
sabotage with `git checkout -- <file>` when you're done.

## Part 2: the † commands

Registering a command adds it to the differential generator automatically, so once it's in the
right `*Commands` array, `OPS=10000 npm run test:diff` compares it against Redis 7.4 for you.
Ask the reference server whenever you're unsure: `docker compose exec redis redis-cli <command>`.

General recipe for each one:

1. Find its row in spec section 8 (arity, flags) and add a `CommandSpec` next to its siblings.
2. Check every argument before changing anything (rule 4).
3. Read with `db.lookupRead`, or `db.lookupWrite` for a write; after a change, call
   `db.signalModifiedKey(key)` once per key (rule 5).
4. If it's random or relative, rewrite its propagation (rule 6, spec 9.5).
5. Write an integration test with its happy path and its errors, then run the differential test.

Start with the three the spec calls out: SETEX and PSETEX (a propagation rewrite) and SMOVE
(two keys and WATCH).
