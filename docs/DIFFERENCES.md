# Differences from Redis 7.4

MiniRedis aims to give the same replies as Redis 7.4 (spec rule 3). These are the intentional differences, each with its reason. A row is added whenever the differential test forces a decision.

| Area                                                                                          | Redis 7.4                                                                                                                | MiniRedis                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OBJECT ENCODING                                                                               | listpack, intset, quicklist, hashtable, skiplist, int, embstr, raw                                                       | the same names minus listpack and intset                                                                                                                                                        |
| SCAN family on small collections                                                              | everything in one call                                                                                                   | paged like big ones                                                                                                                                                                             |
| SCAN cursors; KEYS, SMEMBERS and HGETALL order                                                | from SipHash                                                                                                             | from our hash: different values and order                                                                                                                                                       |
| INCRBYFLOAT, HINCRBYFLOAT                                                                     | 80-bit long doubles                                                                                                      | 64-bit doubles; last digits can differ                                                                                                                                                          |
| Largest bulk string                                                                           | 512 MB                                                                                                                   | 64 MB (V8's string limit)                                                                                                                                                                       |
| Memory numbers                                                                                | measured by the allocator                                                                                                | estimates (section 10.5)                                                                                                                                                                        |
| Snapshot file                                                                                 | RDB                                                                                                                      | our own format (section 11.2)                                                                                                                                                                   |
| AOF                                                                                           | multi-part directory with a manifest, optional RDB preamble                                                              | one file of commands (ADR 0009)                                                                                                                                                                 |
| BGSAVE                                                                                        | `fork()` and OS copy-on-write                                                                                            | time slices and copy-on-write in code                                                                                                                                                           |
| FLUSHDB during a BGSAVE                                                                       | the forked child finishes and saves the dataset as it was before the flush                                               | the job is aborted (spec 9.8): without `fork()`, keeping its point in time would mean saving every key at once through the copy-on-write hook (ADR 0010). FLUSHALL aborts it in both            |
| DEBUG RELOAD                                                                                  | empties the data, then loads; a failed load leaves it empty. Takes MERGE, NOFLUSH and NOSAVE                             | loads into fresh databases and swaps them in only if the whole file checked out, so a failed load leaves the data as it was; no options                                                         |
| BGSAVE log lines                                                                              | `Background saving started by pid <child>`, plus the fork's CoW report                                                   | `Background saving started` (there is no child) and `Copy-on-write saved <n> of <total> keys`                                                                                                   |
| DEBUG DIGEST                                                                                  | Redis's algorithm                                                                                                        | ours; compare MiniRedis with MiniRedis only                                                                                                                                                     |
| Replication                                                                                   | with any Redis, chained replicas                                                                                         | MiniRedis only, no chains                                                                                                                                                                       |
| Auth                                                                                          | ACL users                                                                                                                | one password                                                                                                                                                                                    |
| INFO                                                                                          | dozens of fields                                                                                                         | the fields in section 13.1                                                                                                                                                                      |
| Multibulk count in a request                                                                  | up to INT_MAX (2,147,483,647)                                                                                            | up to 1,048,576, then `invalid multibulk length` (spec 7.4: a client can't make us expect two billion arguments)                                                                                |
| Bytes after a bulk in a request                                                               | the two bytes are skipped unchecked (`$4\r\nPINGxx` runs PING)                                                           | must be `\r\n`, or `-ERR Protocol error: expected '\r\n' after bulk` and the connection closes (spec 10.1)                                                                                      |
| A NUL byte in a request header line                                                           | `strchr` stops at it, so Redis waits for more data until the 64 KB limit                                                 | the line is parsed and rejected at once as an invalid length. Both reject the frame; only the timing differs                                                                                    |
| Doubles that sit exactly halfway between two 17-digit decimals                                | Grisu2 (fpconv) picks one digit, e.g. `1234567890123456.7`                                                               | JS's shortest round-trip digits pick the even one, `1234567890123456.8`. Both parse back to the same double                                                                                     |
| COMMAND INFO                                                                                  | Redis's flags, ACL categories, tips and key specs                                                                        | our flags; categories derived from them (`@read`, `@write`, `@admin` …); no tips; one range key spec per command, flagged `RO access` or `RW update`                                            |
| COMMAND DOCS                                                                                  | per-command documentation                                                                                                | `unknown subcommand`, so `redis-cli` falls back to its built-in help, as it does with servers older than Redis 7                                                                                |
| CONFIG SET port                                                                               | allowed at runtime                                                                                                       | `can't set immutable config` (spec 5 marks `port` immutable)                                                                                                                                    |
| CONFIG directives                                                                             | about 200, plus aliases such as `slave-read-only`                                                                        | the table in spec 5 only, no aliases; `loglevel` has no `nothing`; CONFIG HELP has no REWRITE                                                                                                   |
| `proto-max-bulk-len` bounds                                                                   | 1 MB to LLONG_MAX                                                                                                        | 1 MB to V8's largest string (`buffer.constants.MAX_STRING_LENGTH`)                                                                                                                              |
| UNLINK                                                                                        | frees large values on a background thread                                                                                | the same as DEL (one thread, nothing to hand off to)                                                                                                                                            |
| GETDEL propagation                                                                            | rewritten to `DEL key`                                                                                                   | propagated as `GETDEL key`; replays to the same state                                                                                                                                           |
| INCRBYFLOAT with a result beyond the double range (`1e999`)                                   | accepted (80-bit long double range)                                                                                      | `ERR value is not a valid float`; doubles top out near 1.8e308                                                                                                                                  |
| `keyspace_hits` / `keyspace_misses`                                                           | counted by every read lookup, TYPE, EXISTS, TTL, PTTL, GETEX and SET … GET included                                      | counted only by `lookupRead`: spec 6.1 has TYPE, EXISTS, TTL and OBJECT use `peek`, and rule 5 has writes (GETEX, SET … GET) use `lookupWrite`                                                  |
| Deadlines past 2^53 ms (year 287,396), e.g. `PEXPIREAT k 9223372036854775807`                 | stored exactly as int64                                                                                                  | stored as a double, so PTTL's last digits can differ; the propagated PEXPIREAT still carries the exact int64                                                                                    |
| DEBUG                                                                                         | dozens of subcommands                                                                                                    | DIGEST, DIGEST-VALUE, RELOAD, LOADAOF, SLEEP, SET-ACTIVE-EXPIRE; DIGEST-VALUE hashes the value only, without Redis's TTL marker                                                                 |
| `SRANDMEMBER key <negative count>`                                                            | loops the full count, up to -9223372036854775807                                                                         | at most -1,048,576 (the largest request array, spec 7.4), else `ERR value is out of range, value must between -1048576 and 9223372036854775807`: one thread must never loop for hours (rule 11) |
| SPOP without a count that takes the last member                                               | propagated as `SREM key member`                                                                                          | propagated as `DEL key` (spec 9.5); replays to the same state                                                                                                                                   |
| A stored score of `-0`                                                                        | kept as `-0` once a zset is big enough to be a skip list (over 128 members); dropped to `0` in a small (listpack) one    | always stored as `0`, like a small zset. Replies that compute a score (ZINCRBY, ZADD INCR) still say `-0`, as in Redis                                                                          |
| EXEC with exactly one write                                                                   | propagated as the bare write; MULTI … EXEC only wraps two or more records (`propagatePendingCommands`)                   | always wrapped in `MULTI` … `EXEC` when anything was written (spec 9.5); replays to the same state                                                                                              |
| Sharded pub/sub, PUBSUB HELP                                                                  | SSUBSCRIBE, SPUBLISH, PUBSUB SHARDCHANNELS and SHARDNUMSUB, PUBSUB HELP                                                  | not built (spec 8.7 lists none of them; there is no cluster); they reply `unknown command` or `unknown subcommand`                                                                              |
| BLPOP, BRPOP and BLMOVE timeouts in hex (`0x10`) or past the double range (`1e400`, `1e-400`) | read as an 80-bit long double (`strtold`): hex is accepted, `1e400` gives `timeout is out of range`, `1e-400` waits 1 ms | read like every other double here (`parseStrictDouble`): all three give `timeout is not a float or out of range`                                                                                |
| AOF write under `everysec` while a background fsync is still running                          | postponed for up to 2 seconds (`aof_flush_postponed_start`), then written anyway                                         | written at once, every turn: the fsync runs on libuv's thread pool and doesn't hold the write back                                                                                              |
| A damaged AOF at startup or DEBUG LOADAOF                                                     | `Bad file format …` / `Unexpected end of file …`, pointing at `redis-check-aof --fix`                                    | the same messages, plus the byte offset of the bad record; there is no check tool, so the fix is to truncate or repair at that offset                                                           |
| `-MISCONF` reason text                                                                        | `strerror(errno)`                                                                                                        | glibc's wording for the common disk errors (ENOSPC, EIO, EDQUOT, EROFS …), else Node's own message (`src/utils/errno.ts`)                                                                       |
| `CONFIG SET appendonly yes` when the rewrite can't start (the temp file can't be created)     | an error (`Unable to turn on AOF. Check server logs.`); the AOF stays off                                                | `OK`; the AOF waits for its first rewrite, which serverCron retries every 5 seconds (ADR 0012)                                                                                                  |
| BGREWRITEAOF log lines                                                                        | `Background append only file rewriting started by pid <child>`, plus the fork's CoW report                               | `Background append only file rewriting started` (there is no child)                                                                                                                             |
